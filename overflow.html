Circuit switching

When an interrupt occurs, the CPU core stops its current task and runs a kernel routine. The system saves the current context of the running process so it can be restored later, effectively suspending and then resuming the process. This context is stored in the Process Control Block (PCB) and includes CPU register values, process state, and memory-management information. In general, a state save of the CPU is performed, whether it is in user mode or kernel mode, followed by a state restore to continue execution. Switching the CPU to another process requires saving the current process state and restoring the state of another process. This operation is called a context switch. During a context switch, the kernel saves the context of the old process in its PCB and loads the saved context of the new process. Context-switch time is considered pure overhead because the system does no useful work during this period. The speed of switching depends on factors such as memory speed, the number of registers to be copied, and the availability of special instructions, and it typically takes a few microseconds.Context-switch time is highly dependent on hardware support. Some processors provide multiple sets of registers, allowing a context switch to occur by simply changing the pointer to the current register set. However, if there are more active processes than available register sets, the system must copy register data to and from memory as usual. Additionally, more complex operating systems require more work during a context switch. Advanced memory-management techniques may require extra data to be switched, such as preserving the address space of the current process and preparing the address space for the next process.
